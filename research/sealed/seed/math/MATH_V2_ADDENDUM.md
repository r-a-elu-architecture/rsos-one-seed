# The mathematics of the seed, version 2 addendum (20 Nov 2026, ~08:20 Vilnius)

Private. Adds exact derivations and their confirmations to `MATH_V1.md` (unchanged, sealed).

## A1. The time-window law (exact, periodic windows)

Let a host be reachable during a window of length U·P in every period P (0 < U < 1), and let an operation of n reads
start at a uniformly random time and last T(n) = δ·(n − 1). It fails if any read falls outside a window. For
T(n) < U·P it fails exactly when it starts in an interval of length P − U·P + T(n), so

  P(fail | n) = (1 − U) + δ·(n − 1) / P.

Failure grows **linearly in duration**, not geometrically in n: a time-class host. Confirmed (SPHERE2, orbit node,
U = 0.7, P = 100, δ = 0.01): predicted 30.00 / 30.01 / 30.49 / 32.99 %, measured 29.84 / 29.97 / 30.55 / 32.95 %.

## A2. Error events (general form)

If errors are generated by windows of a renewal process, an operation spanning duration T meets
n_eff ≈ 1 + T / τ̄ independent windows (τ̄ the mean window cycle). Short operations (T ≪ τ̄) fail at the single-window
rate whatever n is; long ones accumulate windows and their failure rises with n. Confirmed on the real engine
(SQLITE2): fast reads 28.5 → 33.7 % from 1 to 300 reads; reads slowed to span many writer cycles 30.7 → 72.0 %.

## A3. The corollary of Theorem 1, exactly (exchangeable unavailability)

If exactly k of N elements are unavailable in an epoch, chosen uniformly, an operation reading n of them fails with

  P(fail) = 1 − C(N − k, n) / C(N, n),

while the compounding bound with ε = k / N is 1 − (1 − k / N)^n. Since (N − k − i)/(N − i) < (N − k)/N for i ≥ 1,
P(fail) exceeds the bound for every n ≥ 2 (successes are negatively associated). For N = 300, k = 10, n = 50:
84.34 % against 81.64 %. Confirmed with ε measured inside the operations (SPHERE3): 84.38 % against 81.56 %, +2.82 pp,
about 7 standard errors.

## A4. Law 2 (blind operation), sharpened by A2

A blind operation sends one request and receives one reply; on a time-class host each message spans one window, so
P_blind = 1 − (1 − μ)² regardless of n, and blind operation gains nothing over a short pull (OPS2). On an element-class
host or for long operations (n_eff > 2), blind wins. This is why blind operation won on the network and ledger and not
on the fast SQLite reader.
