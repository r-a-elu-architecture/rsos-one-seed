For organisations

When several AI agents share a configuration, a ticket, a ledger or a plan, each keeps its own copy, and the copies drift. RSOS Core moves every value computation out of the model and into a small deterministic runtime, and lets you check and repair any copy without a model call.

Run a pilotTechnical specification

What you can rely on

Exact values

Arithmetic, caps, conditions and bulk reassignments are computed by the runtime, never written by the model. Across 256 benchmark tasks on six models, every final state was exact.

Less data to the planner

The planning model sees key names, not values. In the measured protocol an auditor model checks each step and sees the values of the keys that step read and changed; an audit without values is a planned test.

Audit trail

Every step is a short readable program with a digest, its diff and the resulting state digest. Replaying the log reproduces the state exactly.

Drift repair at no model cost

Any agent's copy is compared by digest and restored from the agreed state with zero model calls.

Vendor neutrality

Measured on models from Anthropic, Google, Mistral and OpenAI with the same prompts and the same runtime.

Small surface

Eight operations, six error codes, one JSON IR. Readable in an afternoon; portable to another language from the specification and tests.

Where it fits

Core sits between your agents and the state they share. It does not replace your orchestration framework, model provider or database.

Measured so far on StateBench, a synthetic benchmark of configuration-style key–value state with 30 to 300 keys. Results on your own workflows are what the pilot is for.

A pilot in five steps

Each step has a measurable result, so you can stop at any point with a clear answer.

  1. Pick one workflow. Choose one where agents share state and where an error is costly: an incident runbook, a pricing table, an access list.
  2. Map the state to keys. Flatten it into dotted keys with text values, for example auth.timeout_ms. Record what the agents change today.
  3. Score your current agent. Run your existing setup on StateBench and on a replay of your own change history. Count exact final states and tokens per correct task.
  4. Add the runtime. Connect the MCP server or the Python library and switch the planner to key names only. Run the same tasks.
  5. Decide on the numbers. Compare exact final states, cost per correct task and audit effort. Keep the logs; they replay with zero model calls.

Limits, stated plainly

These are open, and each is a planned or running test.

  • One benchmark family, 16 tasks per cell. Larger and more varied task sets are next.
  • The strongest rival designs, a tool-calling agent and a code-writing agent, have not yet been run head to head.
  • State is flat key–value text. Nested data must be flattened.
  • The state digest detects accidental drift; it is not a security control.
  • Maintained by one author. There is no commercial support contract today.
